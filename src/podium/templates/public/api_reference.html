Overview

The Podium API is organised around REST: predictable resource URLs, JSON request and response bodies, standard HTTP verbs and status codes. Timestamps are ISO 8601 in UTC, for example 2026-10-03T18:00:00Z. Every record has a stable public id with a type prefix — evt_ events, prj_ projects, tm_ teams, usr_ accounts, crt_ criteria, prz_ prizes, trk_ tracks, whk_ webhooks — and imported data keeps the ids it arrived with (the sample event's judges are jdg_…).

Quick start

  1. Create a token on your account page. Read-only is enough to read; it is shown once.
  2. Keep it in your environment, never in code or a repository.{{ code_block("Shell", "export PODIUM_TOKEN=pdm_…") }}
  3. Make a request. Public endpoints need no token at all.{{ code_block("Your first request", "curl " ~ ref.base_url ~ "/api/v1/events") }}

The version lives in the path: /api/v1 only ever gains fields. This page is rendered from the OpenAPI 3.1 document the server generates, so the two cannot disagree.

Authentication

Personal tokens

Create a token on your account page and send it as Authorization: Bearer pdm_…. A token is shown once, carries exactly your permissions, and is either read-only (any request other than GET gets 403) or read and write. Tokens expire after 90 days unless you choose otherwise, and can be revoked at any time.

{{ code_block("With a token", "curl " ~ ref.base_url ~ "/api/v1/me \\\n -H \"Authorization: Bearer $PODIUM_TOKEN\"") }}

Browser sessions

Same-origin requests from a signed-in browser are accepted with the session cookie. Mutating requests from a page must also send the CSRF token (X-CSRF-Token), which the web app does for you.

Who can call what

Every endpoint below states who may call it. Roles belong to an event, not to an account: the same person can organize one event and judge another. An instance admin passes every check.

  • Public no sign-in; anonymous voters are identified by the event's voting mode (account, emailed code or link).
  • Signed in any account; the service layer then limits what is returned (a judge only ever sees their own reviews).
  • Team member a participant on a team in that event.
  • Judge of the event accepted a judge invitation for that event.
  • Event organizer created the event or was added as a co-organizer.

Errors

Every error, from any endpoint, has the same shape. code is stable and machine-readable; message is written for people and is also sent as the X-Podium-Message header. A 422 adds errors, a map from field name to what is wrong with it. A 429 adds Retry-After.

Webhooks

Organizers register endpoints under Integrations (or with the webhook endpoints below). Each delivery is a JSON POST with three headers: X-Podium-Event (the type), X-Podium-Delivery (a unique id — use it to ignore duplicates) and X-Podium-Signature, an HMAC-SHA256 of the raw body with the webhook's secret, formatted sha256=<hex>. Verify it before trusting the payload.

{{ code_block("Verifying a signature (Python)", "import hashlib, hmac\n\nexpected = \"sha256=\" + hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()\nassert hmac.compare_digest(expected, headers[\"X-Podium-Signature\"])") }}

A delivery counts as accepted on any 2xx within 5 seconds. Otherwise it is retried after 30 seconds, 5 minutes and 30 minutes, then marked failed — except for a 4xx other than 408, 425 or 429, which is final. Failed deliveries can be resent from Integrations or with the redeliver endpoint, and Send test queues a ping through the same path.
